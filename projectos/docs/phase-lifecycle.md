# ProjectOS Phase Lifecycle

```
prompt -> implement -> local validate -> evidence pack -> owner/advisor review -> closure
```

1. **Prompt** — phase manifest defines id, type, objective, scope, allowed/forbidden paths+actions,
   required validators/reviews/evidence, approval gates, rollback plan, closure criteria, report path.
2. **Implement** — Claude makes only the changes inside allowed paths.
3. **Local validate** — run `npm run validate`; all validators must pass.
4. **Evidence pack** — produced from the standard template into `knowledge/reports/`.
5. **Review** — owner/advisor review the evidence.
6. **Closure** — only Murad/ChatGPT mark a phase CLOSED. Claude never self-closes.

A phase that touches a gated action (deploy/DB/real-send/payment) must stop and request explicit
owner approval before performing it.
## Reviews in the lifecycle

Between **implement** and **evidence pack**, a phase may declare equiredReviews (e.g. code/security/database/test/quality-gate/silent-failure). Reviews are dispatched only on owner/advisor instruction (eviewDispatchPolicy: manual-owner-or-advisor), never autonomously. Their output is captured in the evidence pack as evidence — recommendation is not approval. Closure still requires Murad/ChatGPT. See [ecc-review-wiring.md](ecc-review-wiring.md).

## Reporter

Evidence packs, pre-push review packs and closure skeletons can be generated by the local phase reporter (projectos/scripts/create-*.cjs) and validated with 
pm run validate:reporter. Generation is mechanical and local-only; it does not approve or close phases. See [phase-reporter.md](phase-reporter.md).

## Staging deploy preparation

Before a staging deploy phase, the deploy guard validates the request and target and generates a plan + result skeleton (no deploy). The owner/advisor decides approval; ProjectOS never executes the deploy. See [staging-deploy-guard.md](staging-deploy-guard.md).

## Proof preparation

Before a controlled staging proof phase, the proof factory validates the request and target and generates a proof plan, evidence skeleton and cleanup plan (no execution). The owner/advisor decides approval; ProjectOS runs no proof or cleanup. See [proof-factory.md](proof-factory.md).

## Drift detection

Before proof or staging work, the drift detector compares expected vs observed static snapshots and produces a drift report (findings, severities, blockers). It runs no live inspection and no repair; the owner/advisor classifies findings. See [staging-drift-detector.md](staging-drift-detector.md).
